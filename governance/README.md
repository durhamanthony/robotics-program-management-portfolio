# Robotics Program Governance Library

This folder contains the cross-program controls used by all five portfolio scenarios. The scenario folders contain the project-specific evidence; this folder defines how a robotics project or program manager governs the work.

## Control set

| Control | Purpose |
|---|---|
| `PROGRAM_MANAGEMENT_PLAN.md` | Defines lifecycle, workstreams, stage gates, and management approach |
| `DOCUMENT_CONTROL.md` | Establishes naming, versioning, approval, retention, and public-sanitization rules |
| `COMMUNICATIONS_AND_MEETING_PLAN.md` | Defines audiences, cadence, inputs, outputs, and escalation paths |
| `STATUS_REPORT.md` | Provides a concise executive status format and a filled portfolio example |
| `QUALITY_MANAGEMENT_PLAN.md` | Connects requirements, reviews, test evidence, defects, and acceptance |
| `CHANGE_CONFIGURATION_CONTROL.md` | Governs baseline changes to scope, schedule, cost, hardware, software, and site configuration |
| `RESOURCE_AND_CAPACITY_PLAN.md` | Defines roles, loading, coverage, and resource-risk management |
| `PROCUREMENT_VENDOR_MANAGEMENT.md` | Governs SOWs, suppliers, lead times, scorecards, warranties, and acceptance |
| `TRAINING_CHANGE_ADOPTION.md` | Plans operator, support, field, and stakeholder readiness |
| `CYBERSECURITY_DATA_GOVERNANCE.md` | Defines minimum controls for identity, remote access, telemetry, privacy, and evidence handling |
| `BENEFITS_AND_CLOSEOUT.md` | Governs benefits measurement, operational handoff, lessons learned, and closure |

The CSV registers are working controls rather than decorative examples. In a live project, the program manager assigns owners and dates, reviews the registers weekly, and links each entry to the system of record.

## Scenario notice

These simulations are fictitious generic scenarios for demonstration purposes only.
